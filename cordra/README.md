# Local Cordra editorial rules

The Marketplace API enforces proposed/zero rating and protects editorial fields. For defense in depth, install the same hook in each Cordra Type (TaxonomicExpert and TaxonomicService), alongside the corresponding bounded JSON schemas under src/sources/dataModel. The hook source is based on Cordra's documented beforeSchemaValidation lifecycle, https://www.cordra.org/documentation/design/javascript-lifecycle-hooks.html.

Local only: sign in to https://localhost:8443 as Cordra admin, Admin > Types, select each type. Back up the current schema and JavaScript, reconcile any pre-existing hook rather than replacing it, then save the matching schema and JavaScript. New records always become proposed with rating 0. A subsequent admin edit can approve or reject. Non-admin direct updates go back to proposed, reset rating and preserve staff comments. Do not add staff group IDs until actual authorization configuration is confirmed; built-in admin is the only privileged reviewer in this local template. API calls use the backend credential and cannot override the API checks.

Test direct create with accepted/99, then approve by editing as admin. Test rating outside 0..100 rejected, and verify existing approved data is unaffected until edited. Use synthetic data only. Existing local schemas are NOT automatically updated by git pull. Do not apply this to production before reviewing actual schema JavaScript, ACLs, staff identities and backup. Production historical data audit/correction remains separate and must be authorized. The frontend and backend public-query changes must be released together. No dedicated reviewer UI is included.
